# 无需人工审核的自动入库

按用户指示，来源人工审核改为可选，不再阻塞文章采集。

- `AUTO_INGEST_DISCOVERIES=true` 为默认值。成功的栏目/搜索发现任务后自动启动一批最多10篇候选正文处理。
- `/coverage` 的“自动采集并提取（10篇）”处理现有积压；无需逐条登记。
- `POST /api/discovery/ingest` 支持 limit 1–30、可选 candidate_ids、retry_failed。
- 自动跳过根页面、栏目、标签、视频等无效文章入口。读取正文后判断所属企业，不把搜索摘要当证据。
- 官方域名匹配企业时使用企业归属；其他来源用当前模型识别报道主角，并要求企业名称及归属引文逐字出现在正文中。不能仅靠标题或背景提及决定归属，可能发现原企业库没有的新企业。
- 背景提及的单个已知公司不能直接成为事件归属。无法明确归属则自动跳过，不要求用户审核。
- 人工拒绝的来源不自动处理。自动登记会标记 decision_method=automatic，并保存动作记录，不冒充人工审核。
- 每篇保存 processing_status 和错误；成功处理不会重复调用模型。采集超时150秒，错误不影响其余文章。沿用 robots、SSRF、限频、大小和原文证据校验。
- 所有处理共享原研究执行锁，运行进度和 API 用量保存到 DiscoveryRun。进程重启会将进行中的候选标记失败，可重试。

实际运行：首批任务 #6 处理10篇，4篇完成、3篇归属不清跳过、3篇访问/大小失败，使用4次模型请求/7,963 tokens。随后任务 #7 也已完成；当前数据库17份 Snapshot、19条事件。

复核发现 #6 中一篇人民网报道的主角为格物通智，而旧的“正文只命中一家已知企业”规则错误归到背景提及的智元。已移除该规则，并依据 Snapshot #11 的真实原文将这次生成的4条事件、证据和来源关联纠正为格物通智，保留修正记录。没有删除历史原文或编造新事实。

19条事件包含演示、规划、研究预览等不同阶段，不代表19条商业部署成果。原文匹配验证不是独立事实验证；企业自述仍保持原标签。自动识别有误判可能，可在事件原文中追溯。

最终80项回归测试通过；归属规则最终调整后6项自动处理定向测试再次通过。前端 TypeScript 和生产构建通过。无浏览器自动化工具，未宣称完整视觉验收。
